# 练琴模式需求

版本日期：2026 年 11 月 15 日。状态：第一版的五步都已完成，用户已经在用；第二版里的等待模式已完成，其余几项见「第二版」。

电钢琴通过 MIDI 接 Logic 发声。练琴模式用来翻弹学习：把一段钢琴转成 MIDI，在 Logic 里校准，再回到 Musicnote 里看着下落音符、跟着原曲练。

## 流程

1. 导入歌曲，选取区间。
2. 确认 BPM 和拍点（可以手填，也可以跟着音乐点节拍）。
3. 拆轨，选钢琴轨，用 MuScriptor 转成 MIDI。
4. 导出到 Logic：原曲片段、钢琴分轨、MIDI 三个文件，起点一致，都是半速。
5. 在 Logic 里对照钢琴分轨手动校准 MIDI，再从第 1 小节开头导出。
6. 把校准后的 MIDI 拖回 Musicnote，自动换回原速。
7. 进入练琴页，配合原曲或分轨练习，也可以关掉伴奏。

第 1 到 3 步沿用现有流程，第 4 到 7 步是新增的。

## 已定事项

| 事项 | 决定 |
| --- | --- |
| 放在哪 | 做进 Musicnote，不做 Logic 插件，不另起一个 app |
| 代码组织 | 练琴是单独的模式和单独的模块，只复用 Core 和音频引擎，不碰和声分析的代码 |
| 琴声 | 从 Logic 出。Musicnote 只读电钢琴的 MIDI 输入，用来亮灯和判断对错 |
| 变速 | 用 Rubber Band 库（R3 引擎），源码直接放进仓库，README 注明 GPL |
| MIDI 回放音 | 默认关闭，用自带音色。不做发给 Logic 的路由 |
| 分手练习 | 第一版不做。以后做的话在 app 里分，不依赖 Logic 拆轨 |
| 片段长度 | 不考虑分段，整首歌也直接整段处理 |
| 界面风格 | 练琴页先用新风格，旧页面以后单独一个阶段再改。琥珀和冷白两套配色都做，可以切换，默认琥珀 |

## 第一版功能

### 打节拍测 BPM

加在现有的「确认 BPM」页面，原有的手填、加减、半速倍速、拍点偏移都保留。

- 原曲播放时点按钮或按键，按点击间隔算出 BPM，填进输入框。
- 点满 4 下开始出结果，点得越多越准。停顿超过 2 秒重新开始算。
- 结果取整到 0.5，之后还能在输入框里微调。
- 同时用点击的时刻算出拍点偏移。算完后节拍器继续响，听着不对可以再调。

### 导出到 Logic

入口在片段页的「练琴」标签。

- 一个按钮导出一个文件夹：`1 原曲（半速）.wav`、`2 钢琴（半速）.wav`、`3 MIDI（半速）.mid`。
- **三个文件都是半速**（2026-11-14 定）：导出是为了对照着校准，慢一半更容易听清每个音。
  - 音频拉长一倍，音高不变。用 Rubber Band 的离线模式处理，比练琴页实时变速的质量高。
  - MIDI 的音符还在原来的拍子上，文件里写的速度是确认过的 BPM 的一半，所以 Logic 的小节线照样对着音乐的小节。
  - 不另外导出原速的文件。
- 三个文件起点相同。
- 在 Logic 里一起拖到第 1 小节开头就是对齐的。
- 文件的起点是片段开头之前最近的一条小节线，不够的部分垫静音（静音也跟着拉长一倍）。这样 Logic 的小节线正好落在音乐的小节上。片段本身从小节线开始时不垫。
- 同一个键在还没松开时又被弹了一次，导出时前一个音在重弹处结束。MIDI 文件本身分不清这种重叠的音该怎么配对。

### 导回校准后的 MIDI

- 把 Logic 导出的 `.mid` 拖进片段。
- 按文件里的速度信息把音符换算成时间，再除以 2 换回原速。所以 Logic 工程用别的速度也没关系，只要音频还在第 1 小节开头。
- 文件是半速还是原速，由音符自己判断：两种速度各读一遍，哪一种和转录结果对得上就用哪一种。所以改成半速之前导出的旧工程、或者在 Logic 里被改回原速的工程，导回来也是对的。两种都判断不出来时按半速读。
- 和转录结果比对位置（转录是从分轨转出来的，等于和分轨比对）。整体错位时提醒，比如放到了第 2 小节，并可以一键移回去。
- 位置一致就直接导入；对不上太多音符时会问一下再导入。
- 踏板（CC64）一起读进来；鼓通道的音符不导入。
- MuScriptor 的原始结果和校准版分开存。再次导入会覆盖校准版，但保留历史版本。

### 伴奏

- 四选一：原曲 / 钢琴分轨 / 去掉钢琴的伴奏 / 关闭。
- 练琴页上有伴奏音量滑杆，播放中可以随时调，下次打开沿用上次的音量。
- MIDI 回放音打开时有自己单独的音量滑杆。
- 「去掉钢琴的伴奏」是其他五轨的混合。确认 MIDI 时，在删掉其他分轨之前自动合成一份（`backing.mp3`）。
- 以前做完的片段其他分轨已经删了，「练琴」标签里有「重新拆轨生成伴奏」，只生成伴奏，不动已有的分轨、MIDI 和和声。

### 练琴页

入口是片段页「练琴」标签里的「开始练琴」。

- 占满整个窗口，侧栏和聊天栏都收起。下方是横放的 88 键，音符从上方落下，落到琴键时对应的键亮起。
- 用的是校准后的 MIDI；还没校准时用转录结果，标题下面会注明「未校准的转录」。
- C 键上标音名。
- 右上角的菜单里可以换配色（琥珀 / 冷白），调提前多久看到音符（2 / 3.5 / 5 / 7 秒）。
- MIDI 里有踏板信息时，舞台右边缘有一条踏板线。
- 「示范音」按钮打开 MIDI 回放音，打开后旁边出现它的音量滑杆。
- 伴奏还没合成或文件找不到时，对应的选项是灰的，鼠标停上去有说明。
- 速度、伴奏、音量、循环按片段记住，下次打开沿用。

### 界面风格

样稿：<https://claude.ai/artifact/Mq6v3EBYMfQcZHBHtYRa85>（私有链接）。

- 整屏暗底，不用描边和卡片，全页只有一个强调色。
- 两套配色可以切换：琥珀（暖灰底、象牙白琴键、琥珀色音符）和冷白（中性灰底、冷白琴键、蓝色强调）。
- 顶部一行是歌名、播放和速度、伴奏；第二行是进度条和 AB 循环；中间是下落音符；键盘贴着屏幕底边。
- 控件偏大，因为练琴时人离屏幕远。
- 2026-11-15 起旧页面也用这两套配色（见 `docs/开发文档.md` 的「视觉系统」），配色的选择全应用共用。

### AB 循环

- 点「循环」从当前小节起循环四小节；`[` 和 `]` 把 A、B 设在当前位置；也可以拖进度条上循环段的两端。
- 循环点吸附到小节线，最短一小节。片段的开头和结尾也算可以吸附的位置。
- 「预备 1 小节」打开时，每一遍从 A 之前一小节开始放。点一下可以关掉。先打一小节拍的方式还没做。
- 衔接处音频做很短的淡入淡出。
- 点进度条跳转，拖动可以连续移动。

### 实时变速

- 范围 0.5 到 1.0 倍，变速不变调。
- 播放中拖动速度条立即生效，速度平滑过渡，没有咔哒声。
- 下落音符、亮灯、AB 循环和伴奏始终同步。

### 读电钢琴输入

- 用 CoreMIDI 读电钢琴的按键，和 Logic 同时接收，互不影响。琴声照常从 Logic 出。
- 电钢琴连上电脑后自动识别，拔掉后自动消失。右上角设置按钮在有键盘连接时变成强调色，点开能看到设备名。
- 按下的那一刻判定对错：
  - 这个音在 0.18 秒内要开始，或者已经在响（长音按晚了），算按对。键变亮，线上闪一下。
  - 其他情况算按错，键变成错误色（琥珀配色下是红色，冷白配色下是橙色）。
  - 0.18 秒按真实时间算，慢速时不会变宽松。
  - 判定结果保持到松开这个键。
- 判定用的是按键事件自带的时间，不受界面刷新快慢影响。
- Logic 自己的虚拟输出端口不算键盘，不读它。
- 延迟校准在设置面板里，范围 ±250 毫秒，画面和按键判定一起移动：
  - 音符碰到线比听到的声音早，或者明明弹在点上却总被判错，往左调。
  - 反过来往右调。
  - 系统报告的输出设备延迟已经自动扣掉，这一项只用来补剩下的偏差。

### 等待模式

开关在进度条那一行的最右边（「等待」），快捷键 `W`。每个片段各自记住开没开。

- **怎么等**：播放到该弹的音就停住，伴奏也停；弹对了继续。弹错的键不会让它往下走。
- **提前和迟到**：比音符早 0.18 秒以内按下算数（和判对错用的是同一个范围）；停住之后多晚按都算。一次按键只算一个音。
- **按时弹就不会停**：不是一到音符开头就停，而是过了开头 0.08 秒还没弹才停。按时弹的人有一半时候会晚几十毫秒，卡着开头停的话音乐会一顿一顿。代价是停下前会听到这个音开头的一小截。
- **和弦**：停住时，所有已经到了开头的音都要按下；它们的键亮着并带一个圆点，按对一个少一个。很短的音在舞台上已经落完，键上的圆点还在。
- **循环**：只等循环范围里的音，预备的那一小节不等。每一遍都从头重新等。循环快绕回来时提前按下一遍的第一个音也算数（关掉预备小节时才会遇到）。
- **从半路开始**：拖动进度、前后跳小节、中途打开开关，都从当前位置重新算，之前的音不用补。
- **没接键盘**：等待不生效，音乐照常播放，开关上会写「没接键盘」；接上后自动生效。
- **示范音**：停住时已经响起的示范音不掐断，让它自然衰减。

## 实现要点

- **代码位置**：不依赖界面的逻辑在 `Sources/MusicnotePractice`（读 MIDI 文件、往返 Logic 的时间换算、位置比对），页面在 `Sources/MusicnoteApp/Practice`。
- **真实片段检查**：`swift run MusicnoteChecks practice <数据目录> <片段 ID> <输出目录>` 对一个做完的片段跑一遍导出和导回。
- **半速音频**：`OfflineStretch` 先让 ffmpeg 写出原速的 WAV，再整段拉长。它事先告诉变速器总长度，所以结果正好是两倍长，原曲 t 秒处的声音落在 2t 秒处。2026-11-14 用一个 25 秒的真实片段量过：长度差不到一个采样，各处的响度曲线和原速文件相差不超过 5 毫秒，没有越走越偏；处理用了 1.5 秒。
- **一个时钟**：变速播放器（`StretchPlayer`）记着「现在听到的是原曲的第几帧」，播放速度只决定这个位置走多快。画面、MIDI 回放音、节拍器和循环都看这一个位置。
- **只有伴奏音频过 Rubber Band**：MIDI 回放音和节拍器按这个位置直接触发，声音本身不经过变速处理。
- **补偿延迟**：
  - 开始播放和跳转时，变速器要先垫一段静音、丢掉开头一段输出，之后输出的第一帧正好是目标位置。
  - 变速器比交出来的声音超前处理一小段，新速度要过这一小段才真正被听到。时钟也晚同样一段才换速度，否则每拖一次速度条就会多偏一点。
- **实测精度**：每半秒一个脉冲，量脉冲实际出现的位置和时钟给的位置差多少。原速 0 毫秒，0.75 倍 3 毫秒以内，0.5 倍 9 毫秒以内；连续换五次速度 11 毫秒以内，不累积；循环 3 毫秒以内。变速器占一个核心的约 2%。这些都在 `swift run MusicnoteChecks` 里。
- **Rubber Band 接入**：源码在 `Sources/RubberBand/vendor`，用它的单文件编译方式做成 SwiftPM 的 C++ 模块，Swift 调它的 C 接口。用 R3 引擎的实时模式，调试版本也开优化。
- **画面的时钟**：引擎每渲染完一个缓冲区，记下这时的位置和这个缓冲区在系统时钟上的结束时刻。画面每一帧用它推算「此刻」的位置，并减去声音从输出设备出来要花的时间，所以音符是平滑下落的，不会一顿一顿。
- **逐帧重画**：舞台的画布必须把「这一帧的时间」当作输入。SwiftUI 只在画布闭包捕获的东西变了时才重画，而位置是画的时候才去引擎里读的；不带上帧时间，播放时画面就不动（2026-11-14 出过这个问题）。真机检查里有一项专门数播放时每秒重画多少次。
- **拖动时不能停的东西**：鼠标按住期间系统的运行循环处在「事件跟踪」模式，只加在默认模式里的计时器会整段停住。刷新时间和小节的计时器要加在 common 模式里；进度条上的播放头和舞台一样逐帧从引擎读位置（2026-11-14 出过拖动时播放头和时间不动的问题）。真机检查里会模拟真实的鼠标拖动来量这些。
- **采样率**：练琴时引擎统一用 44.1 kHz，原曲不是这个采样率时在载入时转换。三种伴奏都载入内存，切换时不用等。
- **真机检查**：`MUSICNOTE_PRACTICE_DRIVE=1` 配合 `MUSICNOTE_ROUTES=analysis:<片段 ID>@3,practice:<片段 ID>` 和 `MUSICNOTE_SNAPSHOT_DIR`，会静音地把练琴页真的播一遍，检查播放速度、播放中变速、循环和快捷键，结果写进 `practice.txt`。
  - 路径里要先开片段页再进练琴页，和实际使用一样。只写 `practice:<片段 ID>` 会漏掉「旧页面离开时做的事」。
  - `MUSICNOTE_PRACTICE_DRIVE=speed` 只检查变速是否生效，十来秒跑完。
- **练琴页占住引擎**：其他页面离开时会清空音频引擎（`stopAll`）。从片段页进练琴页时，旧页面是在练琴页已经把引擎设置好之后才离开的，会把变速、循环和示范音都关掉（2026-11-14 出过速度条完全不起作用的问题）。练琴页开始时先占住引擎，占住期间别的页面的 `stopAll` 不生效；练琴页自己用 `reset`。
- **等待模式的停法**：哪些音弹过了由 `WaitGate`（`Sources/MusicnotePractice/PracticeWait.swift`）记，停在哪由引擎管。
  - 页面告诉引擎一个「不许越过的位置」（`setGate`）：第一个还没弹的音的开头，加上 0.08 秒和输出设备的延迟（都按当前速度换算）。
  - 引擎在音频线程里只渲染到这个位置，前后各有约 3 毫秒的淡出淡入。变速器不重置，所以继续时声音是接上的。
  - 循环绕回的那一刻，引擎自己换成「下一遍的位置」（`afterWrap`），不等主线程发现，否则下一遍开头的音会被冲过去。
  - 真机检查：`MUSICNOTE_PRACTICE_DRIVE=wait`，用虚拟 MIDI 键盘静音跑半分钟。检查没人弹时停在音符后 0.08 秒、弹错不走、弹对继续、按时弹全程不停（原速和半速）、循环第二遍重新等、拔掉键盘后照常播放。
- **速度过渡**：拖动速度条时速度不是硬跳，而是很快滑过去（时间常数 0.02 秒）。加上变速器自身 46 毫秒的超前量，从拖动到听到变化约 0.1 秒。
- **循环衔接**：循环末尾和开头各有约 3 毫秒的淡出淡入。改循环范围时变速器会重新起播。
- **不分段处理**：区间可以是整首歌，直接整段拆轨和转 MIDI，不做分段。转 MIDI 仍然用 MuScriptor medium。

## 建议的实现顺序

1. 打节拍测 BPM。
2. 导出到 Logic 的打包，导回 MIDI 并检查对齐，多存一份去掉钢琴的伴奏。
3. 接入 Rubber Band，引擎支持实时变速。
4. 练琴页：下落音符、键盘亮灯、伴奏切换、AB 循环、速度条。
5. 读电钢琴输入，显示对错，延迟校准。

每完成一步就提交并推送。
